# Фортуната (Морковск, Ozon): максимальное покрытие + автопокупка

Инструмент делает две вещи:

1. **Подбирает билеты** «7 из 35 + 1 из 54» с максимальным покрытием: все числа
   используются одинаково часто, а билеты пересекаются минимально.
2. **Сам заполняет и покупает** эти билеты в приложении Ozon на Android-телефоне
   (через USB-отладку). Можно в полуавтомате: бот тыкает числа, «Купить» жмёте вы.

## Что даёт покрытие (и чего не даёт)

Шансы каждого отдельного билета одинаковы при любых числах, поэтому средний
выигрыш от выбора чисел не зависит. Покрытие меняет другое: билеты не
«дублируют» друг друга, и в каждом тираже заметно чаще хоть что-то играет.

* Билеты подбираются кругами по 5, и каждый круг покрывает все 35 чисел ровно по
  разу. Поэтому если в плане есть хотя бы один полный круг (5+ билетов, подобранных
  за раз), **в каждом тираже гарантированы** минимум 2 совпадения в каком-то билете,
  то есть минимальный приз. У 5 случайных билетов так бывает лишь в 94% тиражей.
* Числа поля 2 не повторяются, пока билетов не больше 54.

Шанс, что хотя бы один билет наберёт (покрытие / случайные билеты):

| билетов | ≥3 совпадения | ≥4 совпадения | угадано число поля 2 |
|--------:|--------------:|--------------:|---------------------:|
| 5       | 58% / 49%     | 9,0% / 8,8%   | 9,3% / 8,9%          |
| 10      | 84% / 74%     | 17,7% / 16,8% | 18,5% / 17,0%        |
| 20      | 98% / 93%     | 33,5% / 30,8% | 37% / 31%            |
| 50      | 100% / 99,9%  | 69% / 60%     | 93% / 61%            |
| 100     | 100% / 100%   | 92% / 84%     | 100% / 85%           |

Для 5+ совпадений разница почти нулевая — такие выигрыши и так редко пересекаются.

## Установка

Нужен Python 3.10+.

```
pip install -r requirements.txt
```

Подбор билетов работает и без этих пакетов; они нужны только для телефона.

Телефон (Android):

1. «Настройки → О телефоне» — 7 раз нажать на «Номер сборки»: включатся режим разработчика.
2. «Для разработчиков» → включить **Отладка по USB**.
   На Xiaomi/Redmi/POCO ещё **«Отладка по USB (настройки безопасности)»** — без неё
   нажатия не проходят.
3. Подключить кабелем, на телефоне разрешить отладку для этого компьютера.
4. Проверить: `python -m adbutils -l` — телефон должен быть в списке.

При первом подключении uiautomator2 сам ставит на телефон свой служебный агент.

iPhone так не управляется. Вариант — эмулятор Android на компьютере (Android Studio
или BlueStacks с включённым ADB), в нём приложение Ozon под вашим аккаунтом.

## Как пользоваться

### 1. Подобрать билеты

```
python -m fortunata plan --carrots 1000          # 1000 морковок / 50 = 20 билетов
python -m fortunata plan -n 20                   # или просто число билетов
python -m fortunata plan --carrots 1000 --price 45   # если билет стоит не 50
```

Сохраняется `plan.json` со списком билетов и печатается оценка покрытия.

* **Докупить в тот же тираж** (появились ещё морковки): `python -m fortunata plan -n 6 --add` —
  новые билеты подбираются с учётом уже имеющихся, покрытие остаётся ровным.
* **Новый тираж** — новый файл: `python -m fortunata plan -n 20 -o tirazh-2.json`.

### 2. Проверить, что бот видит экран

В приложении Ozon откройте Морковск → Фортуната → заполнение билета (пустой билет) и выполните:

```
python -m fortunata inspect
```

Команда покажет, нашлись ли поле 1 (1–35), поле 2 (1–54) и кнопка покупки, и
сохранит в `fortunata-debug/` скриншот с разметкой (зелёное — поле 1,
синее — поле 2, красное — кнопка покупки).

### 3. Первый запуск — под присмотром

```
python -m fortunata buy plan.json --mode fill      # бот заполняет, «Купить» жмёте вы
python -m fortunata buy plan.json --mode confirm   # бот покупает, но спрашивает перед каждым
```

### 4. Полный автомат

```
python -m fortunata buy plan.json --mode auto
python -m fortunata buy plan.json --mode auto --limit 10   # не больше 10 билетов за запуск
```

Прогресс пишется в план после каждого билета: запуск можно прервать (Ctrl+C) и
продолжить — купленные билеты повторно не покупаются.

### Статусы

```
python -m fortunata show plan.json               # билеты и статусы
python -m fortunata mark plan.json 7 bought      # поправить вручную: new / bought / check / skip
python -m fortunata report plan.json --bought    # покрытие купленных билетов
```

## Защита от ошибок

* Кнопки мультипокупки случайными числами бот не нажимает: они отсекаются по
  тексту («случайн», «N билетов», сумма больше цены билета).
* Перед покупкой бот сверяет выбранные числа по экрану (по дереву элементов или по
  цвету клеток). Если выбор не удаётся проверить, бот останавливается, а не
  покупает наугад, и одно число дважды не нажимает.
* Перед нажатием «Купить» билет помечается «проверить». Если связь оборвётся
  посреди покупки, этот билет повторно куплен не будет — проверьте его в «Моих
  билетах» и поставьте статус командой `mark`.
* Когда морковки кончаются, бот останавливается.
* Если подтверждения покупки не видно, в режиме auto бот останавливается,
  а в режиме confirm спрашивает вас.

## Если что-то не распознаётся

Точные надписи в приложении могут отличаться от тех, что заложены по умолчанию.
Всё настраивается JSON-файлом без правки кода:

```json
{
  "buy_button": "(?i)купить за",
  "success": "(?i)(билет куплен|ваш билет)",
  "max_price": 60
}
```

```
python -m fortunata buy plan.json --config my.json
```

Все ключи и значения по умолчанию есть в `fortunata/android/config.py`. Проще всего
выполнить `inspect` на нужном экране и прислать файлы из `fortunata-debug/`
(`.xml` и `.png`): по ним видно, как подстроить настройки.

## Важно

Правила акции «Морковск» могут запрещать автоматизацию. Теоретически Ozon может
аннулировать выигрыш или ограничить участие. Решать вам. Самый осторожный
вариант — режим `fill`: бот только расставляет числа, покупаете вы сами.

## Как это устроено

* `fortunata/game.py` — правила и точные вероятности (гипергеометрия).
* `fortunata/optimizer.py` — подбор. Билеты идут кругами по 5; каждый круг —
  разбиение всех 35 чисел. Отжиг меняет числа местами внутри кругов и
  минимизирует штраф за пересечения всех пар билетов. Штраф для пары с x общими
  числами — сумма по призовым уровням доли «пропавших» выигрышей
  P(оба билета выиграли) / P(один выиграл). Числа поля 2 раздаются без повторов.
* `fortunata/report.py` — оценка: Монте-Карло с подсчётом совпадений сразу по
  всем билетам (битовые плоскости), уровни 6–7 — аналитически.
* `fortunata/android/` — бот: разбор экрана (`screen.py`), покупка (`bot.py`),
  настройки (`config.py`), диагностика (`inspector.py`).
* `tests/` — тесты, включая симулятор экрана Фортунаты (`tests/fake_ozon.py`),
  на котором бот проходит покупку целиком.

Запуск тестов: `pip install pytest pillow && python -m pytest`.
